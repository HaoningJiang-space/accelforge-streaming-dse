# 融合临界容量的标度律（候选 1，第一天，2026-11-14）

**要检验的 X/Y：**
- **X：** 模型越大越受带宽限制，跨算子融合越重要。
- **Y：** 两级 GEMM 链要靠融合获益，片上容量必须超过一个临界值 C*。C* 只取决于两个外侧维度之和 (K+P)，与 batch 和序列长度 M、与中间张量宽度 N 都无关，并且随 (K+P)² 增长。

## 1. 闭式推导（主导项，权重放不下片上的区间）

链为 Y[M,P] = (X[M,K]·W1[K,N])·W2[N,P]，中间张量为 H[M,N]，片上容量为 S。

- **不融合：** H 写回 DRAM 再读回，代价 2MN。每个 GEMM 单独取最优分块，重读项是经典的 2·MKN/√S 和 2·MNP/√S。
- **融合：** H 留在片上。按 m 行分块：片上放 X 的行块和 Y 的累加器，共 m(K+P)；每个行块流式读一次 W1、W2，所以权重流量为 (KN+NP)·M/m。取 m = S/(K+P)，得 N(K+P)²·M/S。

融合更好的条件是 N(K+P)²/S < 2N + 2N(K+P)/√S。令 x = (K+P)/√S，即 x² < 2 + 2x，所以 x < 1+√3：

> **C\* ≈ (K+P)² / (1+√3)² ≈ 0.134·(K+P)²**

M 和 N 都约掉了。这个式子在 N(K+P) 远大于 S、即权重放不下片上时成立。N 很小时，权重本身能放进片上，融合可以很便宜。这正是 CUTLASS 的 back-to-back GEMM 要求 N 小的情形。

## 2. 用精确求解器验证（`exact_crossover.py`，221）

- 用 index-coupling 的精确 v2 前沿（`partitions='dp'`，halving tile）。
- `split` 用 `root_groups=(E1|E2)`、`root_kept=()`，强制 H 经 DRAM。
- C* 取最小的容量，使完整前沿的流量严格低于 `split` 的流量。

| M | N | d=K=P | 精确 C\* | 首次领先 5% 的容量 | 预测 0.134(2d)² | 最大容量处的流量比 |
|---:|---:|---:|---:|---:|---:|---:|
| 16/64 | 64 | 4 | 10 | 10 | 8.6 | 4.2 / 9.0 |
| 16/64 | 64 | 8 | 35 | 35 | 34.3 | 2.6 / 5.0 |
| 16/64 | 64 | 16 | 133 | 133 | 137.2 | 1.8 / 3.0 |
| 16/64 | 64 | 32 | 265 | 521 | 548.9 | 1.4 / 2.0 |
| 16/64 | 16 | 8–32 | 19 | 35–69 | — | 进入 N 小的区间 |
| 16/64 | 4 | 4–32 | 4 | 4–37 | — | 进入 N 小的区间 |

- 在 N ≥ 2d 的区间，精确 C\* 与预测在 2–5% 内相符，d 每翻一倍 C\* 约乘 4。
- M=16 和 M=64 给出完全相同的 C\*，说明与 M 无关。
- N 小时 C\* 由权重驻留决定，与第 1 节对 N 小区间的说明一致。

## 3. 代入真实模型（fp16，主导项估计）

| 链 | K+P | C\* |
|---|---:|---:|
| attention：QKᵀ → PV（d_head=128） | 256 | **17 KiB** |
| FFN，Llama-2-7B（d=4096） | 8192 | **17 MiB** |
| FFN，Llama-2-13B | 10240 | 27 MiB |
| FFN，Llama-2-70B | 16384 | 69 MiB |
| FFN，GPT-3-175B | 24576 | 154 MiB |
| FFN，Llama-3-405B | 32768 | 274 MiB |

同一个式子同时解释了几件事：
- FlashAttention 在任何硬件上都划算：每个 SM 的共享内存约 228 KiB，远大于 17 KiB。
- 融合 MLP 在 GPU 上很少见：单个核需要 17–274 MiB。
- 只有 SRAM 很大的数据流芯片（Groq、Cerebras 一类）有条件做 FFN 级的融合。
- 而且模型越宽，C\* 按 d² 远离现有的 SRAM。
