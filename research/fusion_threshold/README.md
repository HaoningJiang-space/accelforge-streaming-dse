# 融合临界容量：撤回"普适定律"，候选 1 停止（2026-11-14）

**状态：** 下面第 1–4 节是第一天的原始记录，其中"普适 0.134 定律已被精确验证"的结论**撤回**。原因见第 5 节。


**要检验的 X/Y：**
- **X：** 模型越大越受带宽限制，跨算子融合越重要。
- **Y：** 两级 GEMM 链要靠融合获益，片上容量必须超过一个临界值 C*。C* 只取决于两个外侧维度之和 (K+P)，与 batch 和序列长度 M、与中间张量宽度 N 都无关，并且随 (K+P)² 增长。

## 1. 闭式推导（主导项，权重放不下片上的区间）

链为 Y[M,P] = (X[M,K]·W1[K,N])·W2[N,P]，中间张量为 H[M,N]，片上容量为 S。

- **不融合：** H 写回 DRAM 再读回，代价 2MN。每个 GEMM 单独取最优分块，重读项是经典的 2·MKN/√S 和 2·MNP/√S。
- **融合：** H 留在片上。按 m 行分块：片上放 X 的行块和 Y 的累加器，共 m(K+P)；每个行块流式读一次 W1、W2，所以权重流量为 (KN+NP)·M/m。取 m = S/(K+P)，得 N(K+P)²·M/S。

融合更好的条件是 N(K+P)²/S < 2N + 2N(K+P)/√S。令 x = (K+P)/√S，即 x² < 2 + 2x，所以 x < 1+√3：

> **C\* ≈ (K+P)² / (1+√3)² ≈ 0.134·(K+P)²**

M 和 N 都约掉了。这个式子在 N(K+P) 远大于 S、即权重放不下片上时成立。N 很小时，权重本身能放进片上，融合可以很便宜。这正是 CUTLASS 的 back-to-back GEMM 要求 N 小的情形。

## 2. 用精确求解器验证（`exact_crossover.py`，221）

- 用 index-coupling 的精确 v2 前沿（`partitions='dp'`，halving tile）。
- `split` 用 `root_groups=(E1|E2)`、`root_kept=()`，强制 H 经 DRAM。
- C* 取最小的容量，使完整前沿的流量严格低于 `split` 的流量。

- N 小时 C\* 由权重驻留决定，与第 1 节对 N 小区间的说明一致。

## 3. 代入真实模型（fp16，主导项估计）

| 链 | K+P | C\* |
|---|---:|---:|
| attention：QKᵀ → PV（d_head=128） | 256 | **17 KiB** |
| FFN，Llama-2-7B（d=4096） | 8192 | **17 MiB** |
| FFN，Llama-2-13B | 10240 | 27 MiB |
| FFN，Llama-2-70B | 16384 | 69 MiB |
| FFN，GPT-3-175B | 24576 | 154 MiB |
| FFN，Llama-3-405B | 32768 | 274 MiB |

同一个式子同时解释了几件事：
- FlashAttention 在任何硬件上都划算：每个 SM 的共享内存约 228 KiB，远大于 17 KiB。
- 融合 MLP 在 GPU 上很少见：单个核需要 17–274 MiB。
- 只有 SRAM 很大的数据流芯片（Groq、Cerebras 一类）有条件做 FFN 级的融合。
- 而且模型越宽，C\* 按 d² 远离现有的 SRAM。

## 待核对（停止条件）

1. **文献：** FlashFuser（arXiv 2512.12949，用核间互连扩大融合规模）、Orojenesis 全文、Chimera/Welder/BOLT 里是否已经给出这个与 M、N 无关、随 d² 增长的临界值。如果已有，就停。
2. **模型：** 当前只算流量，没有计入重算（LoopTree）、多级存储（L2 与 SMEM）和 SwiGLU 的三权重形式。要在精确求解器中加入 gate/up 分支和多级容量，复核常数。
3. **实际意义：** 在真实形状上，C\* 以上的收益幅度有多大，对应第 2 节表中的流量比。

## 4. 文献初查与一个需要解释的反例（2026-11-14）

- Orojenesis 定性地指出"缓冲大时融合才有效"，也说明"全层融合不一定优于不融合"，但没有给出 C\* 的标度。
- Chimera（HPCA'23）用解析模型选择块执行顺序；BOLT 要求 back-to-back GEMM 的 N 整块放进一个线程块，对应第 1 节的 N 小区间。都没有给出与 M、N 无关、随 (K+P)² 增长的临界值。（Chimera 只看了摘要。）
- **反例：** FlashFuser（arXiv 2512.12949）在 H100 上借助 DSM（≤16×227 KB）融合 Llama-2-7B 的 FFN，m=128。这远低于本文给出的 17 MiB。
  - 解释：第 1 节假设 M 远大于行块 m。当 M(K+P) ≤ S 时，所有行同时在片上，融合总是可行的，但节省的只是 2MN。而此时权重流量约为 N(K+P)，所以收益不超过 1 + 2M/(K+P)。M=128、d=4096 时，这个上限约为 1.03 倍。
  - FlashFuser 报告的是相对 PyTorch 的 kernel 加速和全局访存减少，其中混有单算子实现的差异，不能直接当作融合本身的收益。这一点需要读全文确认。

修正后的定律有两个区间：
- **M ≥ 0.134(K+P)**：融合要获益，需要 S > 0.134(K+P)²。
- **M 更小**：融合总能放得下，但流量收益不超过 1 + 2M/(K+P)。

两者合起来说明：在大 N 的极限下，融合的收益只由一个无量纲量 σ = S/(K+P)² 决定（M 小时还要再乘上 M/(K+P) 的上限）。下一步用精确求解器检验，不同 d、N、M 的收益曲线画在 σ 上能否重合。

## 5. 复核与撤回（2026-11-14）

1. **新颖性已被覆盖。**
   - Saha–Ye（ICML 2024，*I/O Complexity of Attention, or How Optimal is FlashAttention?*）在标准矩阵乘法模型下证明了 Q = Θ(min{L²d/√S, L²d²/S})，并明确区分 S<d² 与 S≥d² 两个区间。attention 本身就是两级 GEMM 链（K=P=d，N=M=L）。所以"容量与外侧宽度平方之比决定执行方式"这个机制已有理论先例。
   - Orojenesis §VI 图 18 对两层 32k×4k×16k、32k×16k×4k 的 GEMM，已经明确给出约 10 MB 以下融合曲线可能劣于不融合。"只有定性观察"这个说法不准确。
   - Chimera 全文 §IV-B/C 已有带容量约束的融合调度解析优化，以及多级存储成本模型。
2. **推导不是必要条件。** 第 1 节只给出一个特定融合调度（整宽 X 行块加 Y 累加器，按行块重读权重）的成本。最优融合 ≤ 这一个调度的成本，所以它不划算并不能推出所有融合都不划算。要得到必要阈值，需要对全部合法融合调度证明下界。不融合侧的 2MKN/√S 口径也没有逐项核清。
3. **精确数据中的反例。**
   - M=16、K=P=32、N=64 时，C=265 的完整搜索流量为 10,752，不融合为 11,264，已经减少 4.55%。该见证会重读 X、回存 Y 的部分和，第 1 节没有覆盖这类方案。用"领先 5%"的 521 代替"首次获益"，是改变了待验证的命题。
   - 复核者另外报告：N=128 时首次获益容量为 521；K=P=8、N=256 时为 35；K=4、P=12、N=256 时为 69。所以在 N ≥ 2d 的区间，阈值仍依赖 N 和宽高比（K/(K+P)）。
   - d=4 时 10 对 8.6 相差约 17%，"全部在 2–5% 内"不成立。
4. **单一 σ 不够。** 除 σ=S/a²（a=K+P）外，还有 μ=M/a、ν=N/a、ρ=K/a 三个独立参数。小 M 区间同样要求 m ≤ min(M, (S−工作区)/(K+P))，不能取消对 S 的要求。1 + 2M/(K+P) 只约束"输入、权重各读一次"这一理想比较，不约束实际 kernel 的加速。FlashFuser 的 2.4× 是相对 PyTorch 的平均全局访存，不是 Llama-2-7B 的单例数据。
5. **硬件结论超出了模型。** "FlashAttention 在任何硬件上都划算""只有大 SRAM 芯片能做 FFN 融合""17 MiB 是单核必需容量"都不成立。它们混淆了数据移动与运行时间、单层容量与多级或分布式容量、统一元素大小与混合精度和累加器。

**结论：** 剩下的只是"把已有的平方尺度换算成 FFN 的容量表"，加上一个特定调度的交叉点估计，不足以作为论文主线。候选 1 停止。可以保留的线索是：有限容量下，融合收益与算子内部的复用相互竞争。
