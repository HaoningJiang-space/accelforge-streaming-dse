## 1. 得到的严格局部结果

在固定总顺序的原生 v2 solve 语法内，如果若干**连续区域**之间的所有共享张量都已由
父级驻留，那么区域内部仍可有多层依赖，各区域 solve 前沿可按峰值 max、额外流量 sum
精确组合。保留完整算子迭代域、写归属与全局角色。

这是已有独立单算子分解的区域扩展；本轮排除了所有“全是独立单算子”的状态。
它没有证明 group 入口可这样组合，也没有允许重排交错的区域，或免费忽略未驻留的共享
数据。证明通过投影原生 Leaf/Hold、Partition、Loop，并反向构造父 Partition 完成。

父响应不必相等：改变一个区域的私有输入驻留状态，只改变该区域投影，其他区域的响应
可复用。全局 max/sum 组合仍要重新计算；新增驻留量仍由调用者计入。

## 2. 核对规模

基线是上一轮三个 DAG 上最快的已有配置：认证顺序代表元 + Prefix + independent_ops。
**原有 Prefix 缓存也作为调用 DAG 节点记录**，避免将共享工作重复算作可删除成本。

| 案例 | 顺序代表元 | 合格条件状态／前沿相等 | 私有输入翻转对 | 其中父前沿不同 | 替换后根执行回放 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 两阶段 Join | 3 | 1,309／1,309 | 1,928 | 595 | 25／25 |
| 非对称 Join | 10 | 6,886／6,886 | 10,381 | 3,579 | 81／81 |
| 混合 Join | 6 | 2,344／2,344 | 4,120 | 1,221 | 51／51 |
| 合计 | 19 | **10,539／10,539** | **16,429** | **5,395** | **157／157** |

这些计数是跨顺序调用次数，不是跨顺序同构类的数量。

* 共记录 206,258 个 solve/group/prefix 缓存条目，所有独占计数与原账本相加吻合。
* 9,807 个合格状态仍有非标量未驻留张量；其中 8,111 个还涉及非标量 X（X 在完整图中
  由分支共享，不要求它在每一个被截取的状态内仍有多个消费者）。
  因而命题的覆盖不限于标量叶子。
* 62 个保存的条件 witness 点通过独立类型/资源解释器检查。
* 普通基线的 157 个根 witness，以及 oracle 组合替换后的 157 个根 witness，累计
  **314 次 cell 执行回放**准确；替换运行另作完整类型检查。两组逐顺序前沿全部相同。
* 21 项测试在本机及 221 通过，含 160 个条件配置、两个 tile 域、K=2/3、写归属、
  group 反例、交错区域守卫，以及 D1 的 `(5,32)` 根见证。

替换运行使用独立 native oracle 构造区域计划，是可执行性核查；没有用它报告加速。

## 3. 相对强基线还能消除多少工作？

把所有合格响应设为零构造成本，然后重算根可达性；仍被其他父状态访问的子响应保留。
第二次计算还加回分解所需的区域 solve 查询依赖。两种上限在这些案例上相同。

| 案例 | DP 工作可省上限 | Pareto 候选可省上限 | Loop Choices 可省上限 | 单次插桩独占时间占比 |
| --- | ---: | ---: | ---: | ---: |
| 两阶段 Join | **11.58%** | 7.51% | 1.33% | 11.75% |
| 非对称 Join | **13.31%** | 10.27% | 6.10% | 12.62% |
| 混合 Join | **6.99%** | 5.05% | **0%** | 5.86% |

全部比例按各顺序的实际工作量加权，不取最好的一个顺序，也不简单平均百分比。
两阶段 Join 的连续分支顺序单独有 25.53% DP 上限，但交错顺序
`EX,E0,E1,H0,H1,Join` 没有一个合格状态；全案例仅为 11.58%。

还需扣除真实的识别、前沿组合、见证构造与缓存管理成本。21,998 次区域请求对应
1,404 个按顺序分别计数的投影键；其中 19 个未在原基线出现（非对称 17、混合 2），
上限把它们也视为免费。因此表格是**乐观工作上限，不是实测加速或效率保证**。
插桩时间占比也不能当作未插桩 wall-clock 的精确拆分。

它证明存在可消去的区域组合，但没有显示足以大幅改变这些 DAG 搜索规模的覆盖。
本轮不启动高效实现计时，不将此规则设为默认，不通过扩大案例或叠加更多开关挽救收益。

## 4. 在一个具体非标量循环中定位剩余耦合

从两阶段 Join 的记录中提取以下真实 group，而不是重新设计另一个玩具求解器：

    E0: U0 = X C0       H0: V0 = U0 D0
    E1: U1 = X C1       H1: V1 = U1 D1

顺序为 `E0,H0,E1,H1`；`I=1,J=1,K=2,L=2,N=2`，外部驻留为空，V0/V1 的最终写出
由父级拥有。该 group 唯一可分块的共同秩是 L，tile=1、循环两次。
尚未解决的义务恰为 **X、V0、V1**，三者当前都占 2 个单元。

归档的八个 child solve 响应如下，容量不包含 caller-held 张量，流量为额外流量：

| 外层保留 | 内层完整前沿 `(local capacity, extra traffic)` |
| --- | --- |
| 无 | `(3,2), (5,0)` |
| X | `(3,0)` |
| V0 | **`(3,2), (4,0)`** |
| V1 | **`(3,2), (5,0)`** |
| V0、V1 | `(3,2), (4,0)` |
| X、V0 | `(3,0)` |
| X、V1 | `(3,0)` |
| X、V0、V1 | `(2,0)` |

X 已保留时，左右两条链之间的未决数据联系消失，符合本轮的区域分解条件。
X 未保留时，不能这样直接独立求解。

`Keep V0` 与 `Keep V1` 具有相同保留量 2、相同外层额外流量 6；但局部容量 4 时，
前者 child 的额外流量为 0，后者为 2。放回两次 L 循环后，总容量 6 下，这两个
**固定 mask 分支**的额外流量分别为 6 与 10。数量、大小、输出类型都相同，仍不能
省略身份和在固定顺序中的位置。这是已知 Residency-count 局限在当前瓶颈中的具体实例，
不是关于全局物理最优性的新增定理。

对八个分支按原生公式 `P=reservation+p; Q=outer_extra+2*q` 合并，精确恢复该
group 的完整前沿：

    (3,14), (5,8), (6,6), (7,4), (8,0)

因此，下一项若继续数学研究，应明确针对“X 尚未驻留时，与两个输出累加状态如何
共同影响可行资源响应”。本轮只定位并复原了这个上下文；尚未证明一个紧凑接口能
消去这三者的联合决策，也未开始新优化器。这个上下文仍只是固定顺序 Grammar 的
一个局部问题，不应把解决它等同于解决一般 DAG。
