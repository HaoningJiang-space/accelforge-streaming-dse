# 资源图方向 B：上限检验（2026-11-14）

**主张：** 计算图的结构（分叉、残差跨度、切宽）决定多核/chiplet 空间映射所需的互连拓扑。

**文献：**
- 由任务图综合专用 NoC 是 2005 年前后就有的领域（SUNMAP、NetChip）。
- Monad、Gemini、Compass 等工作用设计空间探索联合优化 NoP 和映射。

**上限检验（`topo_bound.py`）：**
- 模型：4 层 Llama-7B 规模的 decoder；MoE 用 8 个专家、top-2 路由。
- 映射：层流水，按 FLOP 均衡切成连续的段；权重和 KV 驻留在核内。
- 指标：最忙链路上的字节数，以理想 crossbar 的单端口注入/接收量为基准。

| 场景 | N | ring / chain | 2D mesh（蛇形放置） |
|---|---:|---:|---:|
| decode M=1 | 16 / 64 | 1.00 / 1.19 | 1.00 / 0.69 |
| prefill M=2k | 16 / 64 | 1.00 / 1.19 | 1.00 / 0.69 |
| MoE8 prefill | 16 / 64 | 1.00 / 1.00 | 1.00 / 0.71 |

**结论：** 层流水下最差拓扑（ring）也只比理想 crossbar 差 1.19 倍，低于 1.5 倍的门槛，所以**方向 B 停止**。原因和计算图一侧的发现一致：真实 DNN 图接近一条链（切宽 2–5），按拓扑序连续放置之后，链本身就能以膨胀 1 嵌入 ring 或 mesh。拓扑会成为瓶颈，是在把单个算子拆到多个核上时，此时的通信模式是 all-reduce 或 all-to-all 这类集合通信。它由算子内部的切分决定，不由图结构决定，而且已有大量研究。
