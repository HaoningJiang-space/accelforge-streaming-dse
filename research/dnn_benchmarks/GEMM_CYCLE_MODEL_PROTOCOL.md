# 加入计算效率的周期模型：留出检验（运行前冻结）

[GEMM_FIDELITY_RESULTS.md](GEMM_FIDELITY_RESULTS.md) 显示，只按（容量，流量）选 tile 会比
同预算内最快的 tile 慢 1.8–6.9 倍。原因是 tk 不进入流量，却决定每次迭代的计算效率。本实验
检验一个加入这一维的周期模型，能否在**没见过的形状**上选出接近最快的 tile。

## 冻结的模型

参数在 81 次已接受的外部 tile 运行上拟合，留出检验中**不再调整**：

    周期 = 有用字节数 / 390 + 迭代次数 × (80 + tm·tn / 448)
    迭代次数 = (M/tm)(N/tn)(K/tk)

- 第一项是带宽受限的搬运时间。
- 第二项是每次 K 迭代的固定开销，以及随输出 tile 大小增长的部分。

选定这一相加形式（而不是取两者较大值）的依据是训练集上的选择质量：17 组中 14 组选中最快的
tile，最差慢 1.13 倍。取较大值的形式最差慢 1.26 倍。这是样本内结果，只用于选定形式。

合法性规则由上一批的编译失败归纳：tm ≤ 128 或 tm 为 128 的整数倍。

## 留出形状

全部取自真实网络，均未出现在上一批实验中，(M, N, K)：

- BERT-large（序列 128）：QKV 投影 128×1024×1024、FFN 上投影 128×4096×1024、FFN 下投影
  128×1024×4096；
- GPT-2 small（序列 256）：合并的 QKV 投影 256×2304×768；
- ResNet-50 stage 3 的 3×3 卷积，按 im2col 展开为 784×128×1152。

预算、tile 取值规则同上一批。每个（形状，预算）运行以下 tile：

- 流量选择：流量最小，平局取单元最少。
- 模型选择：预测周期最小。
- 对每个 tk：流量最小的 tile，以及预测周期最小的 tile。

此外，每个形状跑一次原生启发式，再加一个预测编译失败的探针 (784, 128, 64)。共 108 次，见
`results/gemm_cycle_model/plan.json`。

## 冻结的预测

- **G1 合法性**：按规则合法的 tile 全部编译并被接受，探针编译失败。
- **G2 保真度复现**：有用字节数与每通道单元数逐个精确，100%。
- **G3 选择质量**：在可比较的（形状，预算）中，模型选择的周期不超过所跑集合中最快者的
  1.10 倍，这样的组至少占 80%；任何一组都不超过 1.25 倍。
- **G4 相对流量选择的改进**：至少 75% 的组里，模型选择比流量选择快至少 1.5 倍。
- **G5 周期预测误差**：所有被接受运行上的相对误差，中位数不超过 20%。
- **G6 与原生启发式**：只报告。

## 规则

- 只接受数值通过且最终累计审计接受时序的运行。所有失败保留，不重跑挽救。
- 不改模型参数、不加形状、不改候选规则。
- "最快者"只在所跑集合里取，不是全部合法 tile 中的全局最优。这一局限如实报告。

## 判定后果

- **G3、G4 成立**：周期模型可以作为映射选择的目标。论文中容量–流量模型的定位是"精确的
  流量与容量账本"，再加一个经留出检验的周期估计，而不是单靠流量做选择。
- **G3 不成立**：三参数的周期结构不足以外推到新形状，需要更多机制（例如阵列利用率随
  tm、tn 的变化），或者在论文里限定为同形状族内的经验结论。
- **G1 不成立**：合法性规则错误，先修正规则。

所有结论只针对这一后端配置下的单 GEMM。
