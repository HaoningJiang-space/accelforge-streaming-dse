# 单 GEMM 上容量–流量模型的保真度（运行前冻结）

目的：在修复后的 PyTorchSim 上检验我们的（容量，流量）模型对真实层形状 GEMM 是否
可信，以及流量与周期的关系。这是写论文之前必须知道的"模型是否可信"关口，不是
映射搜索加速实验。

## 设置

- 后端：修复后的 PyTorchSim（`repaired_backend_lock.json`），使用 a8c2aa19 起的最终累计
  审计。硬件同既有验证：1 核、2 个脉动阵列、128 通道、每通道 128 KiB scratchpad、16 通道
  HBM2、940 MHz、float32、编译优化 `none`、固定且互不重叠的张量基址。
- 映射族：PyTorchSim GEMM 模板。M、N 在外层分块，K 在内层，输出 tile 驻留。只使用不切
  子块的 tile（子 tile = tile），以避开 N/K 通道对齐限制。
- 形状（取自真实网络，(M, N, K)，Y[M,N] = X[M,K] W[K,N]）：
  - BERT-base（序列 128）：QKV 投影 128×768×768、FFN 上投影 128×3072×768、FFN 下投影
    128×768×3072；
  - ResNet-50 的 1×1 卷积展开：784×512×128（stage 3）、3136×256×64（stage 2）。
- tile 取值：每一维取能整除它的 2 的幂（≥ 8），再加上维度本身。
- 预算：每通道 128 / 512 / 2048 / 8192 个单元（再乘 128 通道 × 4 字节）。
- 每个（形状，预算）选取的 tile：
  - **模型选择**：预算内流量最小的 tile，平局时取单元最少的，再平局时取更大的 tm、tn。
    这就是纯（容量，流量）求解器会给出的映射。
  - 对预算内出现的每个 tk，取流量最小的 tile，以暴露 tk 的作用。
  - 另外，每个形状跑一次原生启发式。
- 共 100 次运行，见 `results/gemm_fidelity/plan.json`。由 `gemm_fidelity.py plan` 生成，
  在运行前提交。

## 冻结的预测

逐次运行的预测写在 plan.json 中。

- **H1（流量保真度）**：每次被接受的运行，其审计的有用字节数都等于
  4·(M·K·N/tn + K·N·M/tm + M·N)。预测 100%。
- **H2（容量换算）**：每通道单元数等于 tm·r(tk)/128 + tk·r(tn)/128 + tm·r(tn)/128，其中
  r(x) 为向上补齐到 128 的倍数。该公式由既有 7 个运行推出，在新运行上作留出检验。预测
  100%。
- **H3（流量最优不是周期最优）**：在跑了至少两个 tile 的（形状，预算）里，至少 75% 的
  情况下，模型选择不是周期最少的；并且周期最少的 tile，其 tk 不小于模型选择的 tk。
- **H4（固定 tk 时流量与周期同向）**：在同一形状、同一 tk、至少 3 个 tile 的组里，流量
  与周期的 Spearman 相关系数，中位数 ≥ 0.8。
- **H5（与原生启发式比较）**：不做方向预测，只报告周期、流量和物理占用。

## 接受与失败

- 只接受同时满足以下两条的运行：数值通过，且最终累计 DMA 审计
  `timing_accepted = true`。
- 编译失败、超时（每次 900 秒）或审计失败的运行，都保留记录并列出，不剔除、不重跑
  挽救。
- 不加形状、不改 tile 规则、不改预算来挽救结论。

## 判定后果

- **H1 或 H2 不成立**：模型与后端的对应有误。先修正对应关系，不做任何周期比较。
- **H1、H2 成立，H3 成立**：（容量，流量）不足以选出好的映射。论文要么把计算效率（tk
  对脉动阵列的利用率）纳入模型，要么明确限定为"流量模型"。
- **H3 不成立**：在这个模板族里，流量最优基本就是周期最优，模型可以直接用于选映射。
- **H4 不成立**：流量与周期即使在固定 tk 时也不同向，说明还有其他主导因素，需要单独
  分析。

所有结论只针对这一后端配置下的单 GEMM。跨算子驻留、融合、能耗都不在本实验范围内。
